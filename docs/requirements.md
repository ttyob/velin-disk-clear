> 文档版本：v0.8  
> 编写日期：2026-09-03  
> 目标平台：Windows 10 / Windows 11（x64）  
> 技术方向：Go 桌面应用  
> 文档状态：需求基线草案，供产品确认、技术设计和任务拆分使用

## 1. 项目概述

### 1.1 产品名称

产品名称：Velin Disk Clear（Windows 磁盘清理管家）。

### 1.2 产品定位

面向 Windows 个人用户的本地磁盘空间管理工具，通过规则扫描、分类清理和 AI 辅助分析，帮助用户了解磁盘空间占用，安全释放 C 盘及其他磁盘空间。

产品重点不是“尽可能多地删除”，而是：

1. 扫描结果清楚，用户知道空间被什么占用。
2. 清理规则可解释，用户知道为什么可以清理。
3. 删除动作可控，重要文件默认不自动删除。
4. C 盘提供针对 Windows、应用缓存和用户目录的专项能力。
5. AI 用于识别、归类和生成建议，不替代用户做高风险决定。

### 1.3 目标用户

- C 盘空间不足，但不了解 Windows 文件结构的普通用户。
- 希望定期清理系统、软件缓存和临时文件的用户。
- 希望快速发现大文件、重复文件、长期未使用文件的进阶用户。
- 需要自定义规则或排除目录的高级用户。

### 1.4 产品目标

- 提供 C 盘专清和任意本地磁盘扫描清理。
- 建立可配置、可扩展、可审计的清理规则系统。
- 提供安全、可解释的 AI 清理建议。
- 让扫描、选择、永久删除和查看记录形成完整闭环。
- 首版以单机桌面应用为主，不依赖账户体系。

### 1.5 成功指标

- 扫描完成率不低于 99%，单个无权限文件不导致全局扫描失败。
- 所有清理结果均可追溯到具体规则、文件和执行时间。
- 默认规则不得删除用户文档、桌面文件、照片、视频或应用业务数据。
- 高风险项目必须二次确认，且默认不勾选。
- 典型 500 GB 磁盘扫描过程中界面保持可响应，可随时暂停或取消。

### 1.6 产品原则

1. **安全优先**：不能确认用途的文件只分析、不默认删除。
2. **结果可解释**：每个候选项都能说明来源规则、风险和删除影响。
3. **用户可控制**：扫描范围、选择结果、清理方式和 AI 数据范围均由用户控制。
4. **基础能力离线可用**：磁盘概览、规则扫描、永久删除和历史记录不依赖网络。
5. **渐进提权**：应用默认以普通用户运行，只在必要动作发生时请求管理员权限。
6. **失败可控**：单项失败不破坏整个任务，执行前必须完成计划确认和文件状态复核。

## 2. 需求来源与范围

### 2.1 主体需求（用户提出）

1. 开发 Windows 系统磁盘清理管家。
2. 支持 C 盘专项清理。
3. 支持其他磁盘清理。
4. 支持基础扫描和清理。
5. 基础清理可配置多种清理规则。
6. 提供特色 AI 清理能力。
7. 提供 GUI 桌面界面。
8. 使用 Go 编写。
9. GUI 采用现代、简约、克制的科技风格，支持亮色与暗色主题，不使用花哨装饰。
10. AI 清理采用专用 Agent，用户可配置 `base_url`、`model` 和 `api_key`。

### 2.2 补充需求（为形成完整产品闭环）

1. 提供磁盘概览、分类统计、大文件分析和目录占用排行。
2. 每条规则包含风险级别、说明、匹配范围、排除条件和默认选择状态。
3. 支持扫描暂停、继续、取消和错误跳过。
4. 清理前展示明细、预计释放空间和风险提示。
5. 文件清理统一永久删除；必须显示不可恢复提示并由用户确认清理计划。
6. 提供白名单、排除路径、清理历史和操作日志。
7. 对管理员权限、被占用文件、符号链接、挂载点和系统保护目录进行专门处理。
8. AI 建议必须说明判断依据、风险和建议动作，禁止静默自动删除高风险文件。
9. 规则支持版本管理与签名校验，为后续在线更新留出接口。
10. 支持跟随系统、亮色、暗色三种主题模式，以及缩放适配和基本无障碍操作。

### 2.3 首版不包含

- 注册表“清理”和所谓一键系统加速。
- 驱动管理、病毒查杀、内存加速、软件卸载等无关能力。
- 企业集中管控、远程执行和多用户云同步。
- 自动清理用户个人文件。
- 未经确认上传文件内容到云端 AI 服务。
- 对系统盘执行磁盘碎片整理。

### 2.4 需求优先级

| 优先级 | 含义 | 范围 |
| --- | --- | --- |
| P0 | MVP 必须完成，不满足则不能发布 | 磁盘概览、C 盘专清、其他盘扫描、规则引擎、NTFS 空间计算、结果确认、安全永久删除、白名单、日志、亮色与暗色主题 |
| P1 | 正式 V1 应完成，可在 MVP 后迭代 | 基础 AI 分析、大文件分析、增量扫描、多用户、云盘保护、扩展应用规则、规则管理、按需提权、计划扫描、托盘通知、自动更新、诊断导出 |
| P2 | 增强与差异化能力 | 高级 AI 方案、虚拟机与容器分析、重复文件、空间趋势、低风险自动清理、规则在线市场、多语言 |

发生工期冲突时，按“安全校验 > 数据保护 > 核心扫描清理 > 使用体验 > AI 与增强能力”的顺序取舍。

### 2.5 典型用户故事

#### 场景 A：C 盘告急

用户发现 C 盘只剩 8 GB，希望快速释放空间。用户进入 C 盘专清，执行快速扫描，查看系统临时文件、浏览器缓存和回收站结果，确认低风险项目后完成清理，并看到实际释放空间。

#### 场景 B：查找其他盘大文件

用户不知道 D 盘空间被什么占用。用户选择“空间分析”，查看一级目录排行和大文件列表，按修改时间筛选，将确定不需要的安装包移入回收站，并将工作目录加入白名单。

#### 场景 C：按目标释放空间

用户希望释放 20 GB，但不理解扫描结果。AI 根据已生成的扫描快照组合一套建议方案，分为“可安全释放”“需要检查”“不建议处理”。用户逐项确认后进入统一清理流程。

#### 场景 D：高风险删除保护

用户勾选了个人大文件。应用在确认页展示完整路径、大小、风险和不可恢复说明；用户取消后文件保持不变，只有明确点击“永久删除”才执行。

#### 场景 E：高级用户维护规则

用户为某款开发工具添加缓存规则，先运行测试扫描，确认规则只命中指定缓存目录，再启用该规则。规则路径超出允许范围时，系统拒绝保存并说明原因。

## 3. 核心概念

### 3.1 扫描对象

- 卷：C、D、E 等可访问的本地固定磁盘。
- 路径：目录或文件。
- 清理项：由规则命中的一个文件、目录或系统维护动作。
- 分类：系统临时文件、浏览器缓存、应用缓存、日志、回收站、大文件等。

### 3.2 风险等级

| 等级 | 定义 | 默认行为 | 示例 |
| --- | --- | --- | --- |
| 低 | 通常可安全重建或明确为临时数据 | 可默认勾选 | 临时目录、崩溃转储、缩略图缓存 |
| 中 | 删除后可能导致重新下载、重新登录或丢失历史记录 | 默认不勾选或明确提示 | 浏览器缓存、下载缓存、应用日志 |
| 高 | 可能影响系统恢复、应用运行或用户数据 | 永不默认勾选，二次确认 | Windows 更新回退文件、休眠文件、用户下载目录 |
| 禁止 | 不允许由通用规则直接删除 | 仅展示或完全跳过 | 注册表数据库、引导文件、活动页面文件 |

### 3.3 清理方式

- 永久删除：所有可执行文件清理的唯一方式，绕过回收站，执行后不可恢复。
- 系统 API：调用 Windows 官方接口完成组件存储、回收站等维护动作。

### 4.1 首页与磁盘概览

首页展示：

- 所有本地固定磁盘的盘符、名称、总容量、已用空间和可用空间。
- C 盘空间告警状态。
- 最近一次扫描时间、最近释放空间和累计释放空间。
- “C 盘专清”“选择磁盘扫描”“AI 分析”三个主要入口。
- 最近清理记录和永久删除结果入口。

磁盘空间告警建议阈值：

- 正常：可用空间大于 15%。
- 警告：可用空间为 5% 至 15%。
- 严重：可用空间小于 5% 或小于 10 GB。

阈值可在设置中调整。

### 4.2 C 盘专清

C 盘专清采用预置规则集，首版至少覆盖：

| 分类 | 扫描内容 | 风险建议 |
| --- | --- | --- |
| 系统临时文件 | Windows Temp、用户 Temp、错误报告临时文件 | 低 |
| Windows 更新缓存 | 已完成更新后可释放的下载缓存 | 中，优先使用系统 API |
| 日志与转储 | 可清理的系统日志、崩溃转储、应用崩溃报告 | 低/中 |
| 回收站 | 当前用户及可访问卷的回收站内容 | 中 |
| 缩略图与图标缓存 | Windows 可自动重建的缓存 | 低 |
| 浏览器缓存 | Edge、Chrome、Firefox 等缓存目录 | 中 |
| 常用软件缓存 | 通过内置规则识别的软件缓存 | 中 |
| 安装与升级残留 | 已确认失效的安装临时目录和升级残留 | 中/高 |
| 休眠文件 | 展示占用并提供关闭休眠入口 | 高，执行系统命令前确认 |
| 系统还原点 | 展示占用和跳转系统管理入口 | 高，不直接批量删除 |
| 用户大文件 | 下载、桌面、视频等目录的大文件 | 高，不默认清理；用户逐项确认后才可永久删除 |

要求：

- 规则必须限定根路径，不能因环境变量异常扩展到整盘。
- 优先使用 Windows 官方清理 API 或受支持命令，不直接删除受保护系统组件。
- 需要管理员权限的规则显示权限标识，扫描和提权应按需进行。
- 系统组件存储不通过普通文件删除实现。

### 4.3 其他盘清理

用户可选择一个或多个非系统盘进行扫描，支持：

- 临时文件、日志文件、缓存目录和回收站扫描。
- 按大小区间、修改时间、扩展名和路径筛选。
- 大文件排行，可配置阈值，默认大于 1 GB。
- 空目录扫描，排除系统目录、隐藏保护目录和用户白名单。
- 重复文件扫描作为后续增强功能，使用“大小预筛选 + 分块哈希 + 完整哈希确认”，不按文件名直接判断重复。
- 自定义目录扫描。

其他盘不得默认将未知文件识别为垃圾文件。未知大文件只能列为“空间分析”结果，由用户决定。

#### 4.3.1 大文件扫描

大文件扫描属于空间分析能力，支持 C 盘、其他固定磁盘和用户指定目录。

- 默认阈值为 1 GB，可配置为 100 MB、500 MB、1 GB、2 GB、5 GB 或自定义值。
- 扫描结果默认按文件大小从大到小排列，显示文件名、完整路径、大小、类型、修改时间、所属目录和建议。
- 可按磁盘、目录、文件类型、大小区间、修改时间和规则建议筛选。
- 对安装包、压缩包、视频、虚拟磁盘、备份、开发依赖和未知文件分别归类，不因体积大就判定为垃圾。
- 所有大文件均设置 `default_selected: false`，不会被“全选推荐项”或文件夹批量选择自动勾选。
- 用户可以主动勾选允许处理的大文件；勾选时展示用途、清理影响和“该文件不会自动恢复”的风险说明。
- 用户个人文件默认不选；主动勾选后仍必须在永久删除计划中再次确认。
- 页面文件、休眠文件、虚拟机磁盘、WSL 虚拟磁盘、数据库、云盘占位符和禁止路径只展示，不提供普通删除动作。
- 大文件扫描支持取消和增量展示，但扫描完成前不能生成可执行清理计划。

### 4.4 基础扫描

#### 4.4.1 扫描模式

| 模式 | 默认范围 | 特点 | 优先级 |
| --- | --- | --- | --- |
| 快速扫描 | 已知低风险系统及应用缓存目录 | 路径少、不计算哈希，目标在数分钟内完成 | P0 |
| 标准扫描 | 启用的全部规则与目录空间统计 | 平衡耗时和覆盖面，作为默认模式 | P0 |
| 深度扫描 | 大文件、长期未使用文件、可选重复文件分析 | 耗时较长，明确提示磁盘负载 | P1/P2 |

扫描模式只决定规则集合和分析强度，不降低路径安全校验标准。

规则包与扫描模式的默认关系：

- 快速扫描：Windows 临时文件、错误报告、可重建缓存、浏览器基础缓存和应用崩溃报告。
- 标准扫描：快速扫描全部内容，加 Windows 更新类缓存、常用应用缓存、旧日志、安装残留分析和目录占用统计。
- 深度扫描：标准扫描全部内容，加开发工具缓存、游戏平台缓存、长期未使用文件、大文件、残留文件和可选重复文件分析。
- 基础扫描完全由确定性规则执行，不依赖 AI Provider；AI Agent 可以选择和调用扫描模式，但不能改变规则安全边界。

#### 4.4.2 扫描流程

扫描流程：

1. 用户选择扫描模式、磁盘或目录。
2. 系统加载启用的规则并完成路径安全校验。
3. 后台并发扫描，持续更新已扫描文件数、已发现空间和当前路径。
4. 用户可暂停、继续或取消。
5. 扫描完成后按分类、规则、目录和风险级别聚合结果。
6. 用户展开分类查看文件明细并选择清理项。

扫描要求：

- 不跟随目录符号链接、目录联接点和重解析点，除非规则明确允许。
- 检测卷边界，避免从选定磁盘意外跨卷扫描。
- 捕获访问拒绝、路径过长、文件被占用等错误并继续任务。
- 扫描过程中限制磁盘 I/O 和工作线程数量，避免明显影响前台使用。
- 文件大小、时间和哈希读取应支持取消信号。
- 对扫描结果建立快照；清理前重新校验路径、大小、修改时间和文件身份。

#### 4.4.3 扫描任务状态

```text
created -> validating -> running <-> paused -> completed
                              |             -> cancelled
                              |             -> failed
                              -> cancelling -> cancelled
```

- 同一时刻只允许一个高 I/O 全盘扫描任务运行；轻量磁盘信息查询不受限制。
- 应用关闭时若有任务运行，应询问取消并退出或最小化到托盘继续。
- 崩溃后未完成任务标为 `interrupted`，不得将不完整结果作为可执行清理计划。
- 扫描结果默认保留 7 天；磁盘卷序列号或规则版本变化后需重新扫描。

#### 4.4.4 空间计算口径

扫描结果同时记录：

- **逻辑大小**：文件内容长度，用于理解文件本身大小。
- **磁盘占用**：文件在卷上实际分配的空间，考虑簇大小、NTFS 压缩和稀疏文件。
- **预计可释放**：执行选定动作后预计真正归还给卷的空间。

计算要求：

- NTFS 硬链接通过卷 ID 与文件 ID 识别，同一文件的多个链接不能重复计算可释放空间。
- 只有删除最后一个硬链接时，才把对应分配空间计入预计可释放。
- 稀疏文件和压缩文件按实际分配空间估算，不能直接使用逻辑大小。
- 文件夹聚合必须去重，不能因同一项目命中多条规则而重复累加。
- 永久删除的预计释放按文件实际分配空间计算，执行后以卷空间变化和单项结果复核。
- 系统接口类清理在无法提前精确估算时显示范围或“待系统计算”，执行后读取卷容量差和工具结果复核。

#### 4.4.5 云盘与占位符保护

- 识别 OneDrive Files On-Demand 及 Windows Cloud Files API 暴露的占位符状态。
- 读取元数据和计算目录大小时不得打开文件正文，不得触发仅云端文件下载。
- 仅云端占位符的磁盘占用按本地实际分配空间显示，不能把云端逻辑大小计为可释放空间。
- 未同步、同步冲突、正在上传或状态未知的文件不得进入删除候选。
- “释放本地副本”是独立系统动作，不等同于删除；只对已完成同步的文件开放并默认不选。
- 不支持的云盘客户端目录默认只分析，不能套用 OneDrive 状态判断。

#### 4.4.6 多用户扫描

- 普通权限只扫描当前用户可访问的配置和缓存。
- 管理员可选择扫描其他本地用户，但必须显示用户列表、扫描范围和隐私提示。
- 不允许仅因管理员身份就默认扫描其他用户的 Documents、Desktop、Pictures、Videos 或聊天数据。
- 每个扫描项记录所属 Windows 用户 SID；筛选、清理历史和审计按 SID 区分。
- 其他用户的中高风险项默认不选，且执行前再次显示所属用户。
- 无法解析 SID、临时配置文件和已删除账户残留只做分析，不自动清理。

#### 4.4.7 增量扫描与任务恢复

- 首次对磁盘执行完整扫描，后续可使用 NTFS USN Change Journal 或文件元数据缓存进行增量扫描。
- USN 不可用、日志回绕、卷序列号变化、规则版本变化或缓存校验失败时自动降级为完整扫描。
- 增量索引只保存扫描所需元数据，不保存文件内容。
- Windows 休眠、磁盘离线、可移动磁盘断开或路径消失时暂停对应卷并记录原因。
- 磁盘重新上线且卷身份一致时允许继续；身份不一致时终止旧任务并要求重新扫描。
- 应用崩溃后只能恢复目录游标和统计进度，恢复前重新验证规则版本与卷身份。
- 未完成或恢复中的扫描结果不能创建清理计划。

### 4.5 扫描结果

结果页支持：

- 显示可释放总空间、项目数量、扫描耗时和跳过项目数量。
- 默认展示文件列表，按大小从大到小排序；分类作为筛选条件和分组信息，不强制先折叠到分类层。
- 查看文件路径、大小、修改时间、命中规则和建议原因。
- 每个分类和文件明细均可查看“当前项用途、清理后影响、是否建议清理”，不能只显示“垃圾文件”。
- 按大小、时间、风险、分类和磁盘筛选排序。
- 全选仅作用于低风险且允许默认选择的项目。
- 中高风险项目需用户主动选择。
- 支持打开所在目录、复制路径、加入白名单和从本次结果排除。
- 对扫描后已变化或不存在的文件显示状态，不继续执行原操作。

#### 4.5.1 文件列表模式

- 文件列表是每次进入结果页的默认模式。
- 每行代表一个可清理或分析文件，显示选择框、名称、路径、大小、修改时间、分类、建议和风险。
- 点击行打开详情抽屉，点击复选框才改变清理选择，避免查看详情时误选。
- 推荐且低风险的规则可按 `default_selected` 初始化选择；中、高风险和分析项始终默认不选。
- 禁止项可以出现在分析结果中，但复选框禁用，并显示禁止原因。
- 大结果集使用虚拟滚动和分页查询，不能一次把所有文件传给 GUI。

#### 4.5.2 文件夹模式

- 顶部使用“文件 / 文件夹”分段控件切换视图；切换只改变展示方式，不改变已选文件集合。
- 文件夹模式按真实目录层级聚合，默认全部收起，可逐级展开和收缩。
- 每个文件夹显示目录名、路径、文件数、候选总大小、已选大小和最高风险等级。
- 展开文件夹后展示直接子目录和文件，深层节点按需加载，避免一次构建整棵目录树。
- 文件夹复选框使用未选、部分选择、全部可选项已选择三种状态。
- 点击文件夹复选框只批量选择其中 `default_selected: true` 且低风险的可清理项。
- 大文件、中高风险、仅分析和禁止项不会因勾选父文件夹而被选中，必须由用户在文件行主动确认。
- 折叠文件夹不会清除内部选择；切回文件列表后仍保持同一选择状态。
- 筛选生效时，文件夹聚合和选择只针对当前可见范围，并明确显示“已筛选”状态。

#### 4.5.3 默认选择规则

1. 每条规则必须包含布尔字段 `default_selected`。
2. 只有 `risk: low` 且 `recommendation: recommended` 的规则可以设置为 `true`。
3. 中风险、高风险、仅分析、不建议和禁止项必须为 `false`。
4. 大文件、长期未使用文件、安装包、压缩包、备份和重复文件始终为 `false`。
5. 用户取消某项后，切换视图、排序或筛选不得自动重新选中。
6. 规则更新不能静默把原来默认不选的规则改为默认选中；此类变化需单独提示。
7. 清理确认页展示“默认选中”和“用户主动选中”的数量，方便识别高风险选择。

#### 4.5.4 规则统计与误报反馈

- 每条规则显示扫描耗时、扫描文件数、命中数量、逻辑大小、磁盘占用和预计可释放空间。
- 清理完成后记录成功数、跳过数、失败数、实际释放空间和“实际/预计释放率”。
- 用户可对单个结果标记“不是垃圾”，操作后立即取消选择并加入本次排除。
- 用户可选择仅本次排除、永久加入白名单或提交匿名规则反馈，三种动作必须分开。
- 匿名反馈只包含规则 ID、应用版本、Windows 版本、文件类型和结果，不包含完整路径、文件名或内容。
- 某规则出现异常失败率或误报反馈时，可以由规则包更新将其远程禁用，但不能远程启用高风险清理。

#### 4.5.5 规则建议与帮助弹窗

- 文件列表、文件夹详情和分类标题旁显示 Lucide `CircleHelp` 问号图标，悬停提示“查看清理建议”。
- 点击问号只打开说明弹窗，不改变勾选状态，也不触发扫描或清理。
- 每条普通规则至少展示：当前项用途、扫描内容、清理影响、是否建议、建议原因、风险、默认选择、处理方式和可恢复性。
- 特殊规则额外展示：为什么需要谨慎、可能影响的 Windows/应用功能、是否需要管理员权限或重启、推荐的手动处理步骤和系统设置入口。
- 特殊规则包括分页文件、休眠文件、系统还原点、Windows.old、驱动包、云盘本地副本、虚拟磁盘、邮件数据库、聊天数据和容器卷。
- 弹窗底部根据规则能力显示“知道了”“打开所在位置”“打开系统设置”等明确操作；禁止项不显示清理按钮。
- 外部帮助链接必须来自签名规则包中的 HTTPS 白名单地址，点击前显示将打开浏览器。
- 文件级别建议继承规则说明，并补充该文件的路径、逻辑大小、磁盘占用和当前状态。

#### 4.5.6 分页文件展示

- 将 Windows 分页文件作为 `windows.pagefile_analysis` 规则展示在“系统占用”分类。
- 扫描 `pagefile.sys`、`swapfile.sys` 及 Windows 返回的分页配置，只读取元数据和配置，不读取文件内容。
- 列表显示用途“虚拟内存与系统内存管理”、当前磁盘占用、所在卷和 Windows 管理状态。
- 该规则为高风险分析项，`default_selected: false`，复选框禁用，不能通过 Cleaner 删除。
- 问号弹窗说明：直接删除或错误缩小可能导致内存不足、应用崩溃和系统转储不可用，通常建议保持“由系统管理”。
- 用户确需调整时，只提供“打开虚拟内存设置”入口，由用户在 Windows 系统界面手动处理。
- 应用不得给出固定推荐大小，不提供“一键关闭分页文件”，也不得把其逻辑大小计入可自动释放空间。

### 4.6 清理执行

清理前：

- 汇总选中项、预计释放空间、各风险等级数量和清理方式。
- 对高风险、永久删除、关闭休眠等操作单独二次确认。
- 检查磁盘状态和权限，必要时触发 Windows UAC 提权。
- 支持将清理计划导出为 JSON 或用户可读报告，包含规则、文件、大小、风险、动作和计划校验摘要，但不包含密钥。
- 支持重新导入由本机导出的计划进行审查；执行前必须重新扫描或逐项复核，过期计划不得直接执行。

清理中：

- 展示总体进度、当前分类、成功/失败/跳过数量。
- 支持取消；已完成项目不回滚，未开始项目停止执行。
- 单项失败不得中断整个任务。
- 清理动作写入本地审计日志，不记录文件内容。

清理后：

- 展示实际释放空间、成功/失败/跳过项目及失败原因。
- 提供清理记录详情。
- 永久删除结果必须明确标记不可恢复，并列出失败或跳过原因。
- 对需重启后删除的文件明确显示并允许撤销计划任务。

### 4.7 规则系统

#### 4.7.1 规则类型

- 路径规则：匹配固定目录、环境变量目录或受限通配路径。
- 文件属性规则：按扩展名、大小、创建/修改时间和文件属性匹配。
- 应用规则：识别已安装应用及其已知缓存目录。
- 系统动作规则：调用经过白名单审核的 Windows API 或固定动作。
- 组合规则：在固定扫描根目录内组合多个条件。

首版不允许规则直接携带任意 PowerShell、CMD 或可执行脚本。

#### 4.7.2 规则字段

建议使用 JSON 或 YAML 存储规则，运行时解析为统一模型：

```yaml
id: windows.user_temp
version: 1
name: 用户临时文件
description: Windows 和应用产生的临时文件，可在需要时重新生成
purpose: Windows 和应用用于保存短期工作数据
clean_effect: 旧文件清理后通常无影响，正在使用的文件将跳过
recommendation: recommended
recommendation_reason: 超过 24 小时的文件通常已不再使用
category: system_temp
platform: windows
enabled: true
risk: low
default_selected: true
requires_admin: false
supported_windows_versions:
  - "10.0.19045"
  - "11"
scope: current_user
size_mode: allocated
recovery_type: none
requires_network_after_clean: false
may_sign_out: false
requires_restart: false
process_guard: []
conflicts: []
last_verified_at: "2026-09-03"
source: "internal-review"
detect:
  type: environment_path
  supported_app_versions: []
  data_directory_strategy: environment
help:
  summary: 清理建议简要说明
  details: 清理影响与风险的完整说明
  special_warning: ""
  manual_steps: []
  learn_more_url: ""
scan:
  roots:
    - "%TEMP%"
  include:
    - "**/*"
  exclude:
    - "**/*.lock"
  min_age: "24h"
  stay_on_volume: true
  follow_reparse_points: false
action:
  type: permanent_delete
safety:
  allowed_roots:
    - "%TEMP%"
  revalidate_before_clean: true
```

必填字段：唯一 ID、版本、名称、分类、用途、清理影响、清理建议、建议原因、帮助摘要、风险、是否默认选择、适用 Windows 版本、用户范围、空间计算方式、可恢复性、联网影响、登录影响、重启要求、进程保护、冲突规则、最后验证时间、规则来源、扫描根目录、匹配条件、清理动作和安全边界。

`default_selected` 必须显式填写，不能省略后依赖程序默认值。规则加载器发现字段缺失或与风险策略冲突时，应禁用该规则并记录校验错误。

应用规则还必须提供安装检测方式、支持的应用版本和数据目录发现方式；调用系统或应用工具的规则必须使用内置动作 ID，不能把任意命令文本写入规则。

高风险、仅分析、不建议和禁止规则还必须提供 `help.details` 与 `help.special_warning`；存在支持的手动处理方式时提供结构化 `manual_steps` 和固定系统设置动作，不允许在帮助文本中嵌入任意可执行命令。

`recommendation` 只允许：

- `recommended`：推荐清理。
- `optional`：按需清理。
- `analyze_only`：仅分析。
- `not_recommended`：不建议清理。
- `forbidden`：禁止清理。

#### 4.7.3 规则管理

- 内置规则不可直接修改，可复制为用户规则。
- 支持启用、禁用、恢复默认和导入导出用户规则。
- 规则保存前进行 schema 校验、路径展开预览和冲突检查。
- 外部规则包必须包含版本、来源、校验和；在线分发时增加数字签名。
- 规则更新前展示变化，保留上一版本以便回退。
- 规则测试模式只返回命中结果，不执行清理。

#### 4.7.4 首批内置规则清单

以下清单是 MVP 的目标规则集。正式实现前，每条规则还需单独完成路径调研、系统版本验证和测试用例。

完整基础扫描规则目录见 [Windows 基础扫描与清理规则目录](./builtin-rules.md)。该目录是内置规则设计、实现和验收的来源，本节只保留首批摘要。

| 规则 ID | 当前项用途 | 清理影响 | 是否建议 | 风险 / 默认 |
| --- | --- | --- | --- | --- |
| `windows.user_temp` | 应用和当前用户的临时工作文件 | 旧文件通常无影响，活动文件跳过 | 推荐，超过 24 小时 | 低 / 是 |
| `windows.system_temp` | Windows 服务和安装程序临时文件 | 旧文件通常无影响，需管理员权限 | 推荐，超过 72 小时 | 低 / 是 |
| `windows.wer_archive` | 已归档的 Windows 错误报告 | 清理后失去旧故障记录 | 推荐，保留最近 7 天 | 低 / 是 |
| `windows.user_crash_dumps` | 应用崩溃调试转储 | 清理后无法分析旧崩溃 | 推荐，非排障用户保留 7 天 | 低 / 是 |
| `windows.memory_dump` | 系统蓝屏或内核故障转储 | 可释放较大空间，但失去蓝屏分析依据 | 按需，必须单独确认 | 中 / 否 |
| `windows.thumbnail_cache` | 图片、视频和文档缩略图缓存 | 会自动重建，首次浏览稍慢 | 推荐 | 低 / 是 |
| `windows.directx_shader_cache` | 游戏与图形应用的着色器缓存 | 会自动重建，首次运行可能卡顿 | 按需 | 低 / 否 |
| `windows.delivery_optimization` | Windows 更新传递优化缓存 | 更新内容可能重新下载 | 按需，使用系统接口 | 中 / 否 |
| `windows.update_cleanup` | 已被替代的更新组件和缓存 | 可能延长后续维护，不能直接删除组件目录 | 按需，使用系统接口 | 中 / 否 |
| `windows.recycle_bin` | 保存已删除文件以便恢复 | 清空后无法从回收站恢复 | 按需，按卷确认 | 中 / 否 |
| `browser.chromium.http_cache` | Edge、Chrome 等网页资源缓存 | 会重新下载，首次访问稍慢 | 推荐，浏览器关闭时 | 低 / 是 |
| `browser.firefox.cache2` | Firefox 网页资源缓存 | 会重新下载，首次访问稍慢 | 推荐 | 低 / 是 |
| `app.electron_crash_reports` | 已识别 Electron 应用崩溃报告 | 清理后失去旧排障信息 | 推荐，保留最近 7 天 | 低 / 是 |
| `generic.old_logs` | 明确日志目录中的历史运行记录 | 清理后失去历史排障信息 | 按需，超过 30 天 | 中 / 否 |
| `generic.large_files` | 帮助定位占用空间的任意大文件 | 可能是重要个人或业务文件 | 默认只分析；用户逐项确认后可永久删除 | 高 / 否 |

以下对象只提供占用展示或系统设置入口，不实现通用文件删除规则：休眠文件、页面文件、系统还原点、Windows 组件存储、驱动包和用户个人目录。

#### 4.7.5 规则冲突与优先级

1. 内置保护名单优先级最高，任何规则不得覆盖。
2. 用户白名单优先于内置规则和用户规则。
3. 同一文件命中多条规则时采用最高风险等级和最保守清理方式。
4. 用户规则不得降低内置规则定义的风险等级。
5. 扫描结果记录所有命中规则，但只生成一个清理项，避免重复计算和重复删除。

### 4.8 AI 清理

#### 4.8.1 产品定义

AI 清理实现为一个专门处理磁盘空间问题的 **Cleaning Agent**。用户可以用自然语言提出目标，Agent 调用应用提供的受控扫描、查询、统计和方案工具，分析本机扫描快照，并生成可解释的清理计划。

Cleaning Agent 是清理流程的智能编排层，不直接获得操作系统文件权限。Agent 不能执行 Shell、PowerShell、CMD、任意 HTTP 工具或任意文件读写；实际清理由本地 Cleaner 在安全校验和用户确认后执行。

#### 4.8.2 AI 首版能力

- 支持对话式清理需求，例如“帮我安全释放 C 盘 15 GB”。
- 根据目标选择快速、标准或深度扫描建议，经用户确认扫描范围后调用本地扫描工具。
- 根据文件元数据识别可能的缓存、备份、安装包、导出文件和长期未使用文件。
- 将未知大文件归类并用自然语言解释用途和处理建议。
- 对扫描结果生成清理优先级，例如“安全释放”“建议检查”“不建议处理”。
- 识别同一目录中的版本化文件、疑似重复导出物和历史压缩包。
- 支持自然语言筛选，例如“找出 D 盘半年没用且大于 2 GB 的安装包”。
- 根据用户目标组合清理方案，显示预计释放空间、风险构成和未达到目标的差额。
- 对用户追问提供上下文解释，例如“为什么建议清理这个文件”和“删除后有什么影响”。
- 清理完成后读取结构化执行结果，向用户总结实际释放空间和失败项目，不掩盖部分失败。

规划中的 AI 页面提供两种模式；当前版本先开放智能扫描，暂不在界面暴露高级对话入口：

1. **智能扫描**：内置“安全释放空间”“查找大文件”“系统深度检查”等目标提示词。Go 先按用户授权范围执行真实扫描，再将扫描项的路径、用途、大小、命中规则、清理影响和风险交给模型分析。结果必须返回真实文件清单，逐项显示说明、建议、风险、置信度和默认勾选状态；默认勾选只能由本地规则允许的低风险可清理项决定。用户修改勾选后进入统一清理计划确认页。
2. **高级对话**：提供清理领域内的多轮自然语言咨询，可询问空间占用、规则含义、文件风险和处理步骤。对话不要求固定文件列表，但如引用文件只能引用当前扫描快照的 item ID。对话结果不能直接创建或执行删除动作。

AI 系统提示词内置且不可被用户覆盖，明确拒绝与 Windows 磁盘扫描、空间分析和清理无关的请求。模型不拥有文件系统、命令、网络或删除工具，Go 扫描器和 Cleaner 分别负责真实扫描与最终永久删除。

#### 4.8.3 Provider 配置

AI 设置页至少提供以下字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 配置名称 | 是 | 用户可识别的名称，例如“本地模型”或“公司网关” |
| `base_url` | 是 | API 根地址，由用户完整填写，例如以 `/v1` 结尾的兼容地址 |
| `model` | 是 | 请求使用的模型 ID，支持手动填写 |
| `api_key` | 云端通常必填 | API 密钥；本机无鉴权服务允许留空 |
| API 协议 | 是 | 首版默认 OpenAI-compatible，后续通过 Provider Adapter 扩展 |
| 请求超时 | 否 | 默认 60 秒，可配置 10 至 300 秒 |
| 最大输出令牌 | 否 | 防止单次返回过大并限制费用 |

配置交互要求：

- 支持新增、编辑、删除多个 Provider 配置，并指定一个当前使用配置。
- `api_key` 输入框默认遮挡，只提供显示/隐藏与替换，不回显完整密钥。
- 提供“测试连接”，使用最小请求验证地址、鉴权和模型，不发送任何磁盘数据。
- 连接成功后继续执行“能力测试”，验证结构化 JSON 输出、工具调用、参数 schema 和取消响应；只有连接与能力均通过才标记为可用 Agent Provider。
- 能力测试不访问本机磁盘，使用内置虚拟扫描样本，并明确列出模型缺失的能力。
- 若接口支持模型列表，则允许刷新并选择；不支持时仍可手动填写模型 ID。
- 展示连接结果和可执行建议，区分鉴权失败、模型不存在、限流、超时、网络错误和协议不兼容。
- 编辑 `base_url` 时展示最终请求地址预览，避免重复或遗漏版本路径。
- 远程地址默认要求 HTTPS；HTTP 只对回环地址默认开放，其他 HTTP 地址需显式开启“不安全连接”并显示风险。
- 禁止 `file://` 等非 HTTP(S) 协议，禁止接口重定向时将 Authorization 发送到不同源。

本地配置只保存非敏感字段及 Credential 引用。密钥保存到 Windows Credential Manager，或使用当前 Windows 用户的 DPAPI 加密，不能明文写入 JSON、SQLite、日志、诊断包或崩溃报告。

建议的非敏感配置模型：

```json
{
  "id": "provider-local-1",
  "name": "本地模型",
  "protocol": "openai_compatible",
  "base_url": "http://127.0.0.1:11434/v1",
  "model": "configured-model-id",
  "credential_ref": "windows-credential://ai-clear/provider-local-1",
  "timeout_seconds": 60,
  "max_output_tokens": 4096,
  "enabled": true
}
```

#### 4.8.4 Agent 工作流

```text
用户目标
  -> Agent 澄清磁盘范围、目标空间和风险偏好
  -> 调用受控扫描/查询工具
  -> 分析不可变扫描快照
  -> 生成清理计划草案
  -> 本地安全策略校验
  -> 用户逐项确认
  -> Cleaner 执行
  -> Agent 总结结构化结果
```

工作流要求：

1. Agent 在目标磁盘或风险偏好不明确时先询问，不能擅自扩大到所有磁盘。
2. 已存在有效扫描快照时优先复用；规则版本、卷身份或文件状态变化时要求重新扫描。
3. Agent 可多轮调用查询与聚合工具，但必须限制最大轮次、超时和令牌消耗。
4. Agent 生成的是草案，只有本地策略校验通过的 item ID 才能进入确认页。
5. 确认页显示 Agent 建议与实际本地清理动作之间的映射。
6. 用户修改选择后，以确认页最终选择为准，无需让模型再次批准。
7. 执行完成后只把结构化结果交回 Agent，不把任意新增文件内容发送给模型。

#### 4.8.5 Agent 工具白名单

首版 Agent 只能调用以下应用内工具：

| 工具 | 权限 | 用途 |
| --- | --- | --- |
| `get_disk_overview` | 只读 | 获取磁盘容量、可用空间和健康状态摘要 |
| `request_scan` | 只读扫描 | 在用户授权范围内创建扫描任务 |
| `get_scan_status` | 只读 | 获取扫描状态和聚合进度 |
| `query_scan_items` | 只读 | 按 item ID、规则、风险、大小和时间查询扫描快照 |
| `aggregate_scan_results` | 只读 | 按分类、目录或规则聚合空间 |
| `explain_rule` | 只读 | 获取本地规则说明、影响和风险 |
| `build_clean_plan_draft` | 创建草案 | 只接受本次有效快照中的 item ID |
| `request_plan_confirmation` | UI 请求 | 打开本地确认页，不执行删除 |
| `get_clean_result` | 只读 | 读取已执行任务的结构化结果 |

以下能力不向 Agent 暴露：任意路径读写、读取文件正文、执行命令、修改注册表、结束进程、下载或运行程序、创建系统任务、永久删除、修改白名单和修改安全规则。

#### 4.8.6 输入与上下文边界

默认只向模型提供最少必要信息：

- 本次用户授权扫描范围内的真实路径、文件名和目录，用于解释具体清理对象；不提供文件正文。
- 扩展名、大小、创建时间、修改时间和文件属性。
- 命中的本地规则、应用归属和哈希分组标识。
- 用户设定的释放空间目标。

默认不上传文件内容、完整用户名、设备名、账号信息和文档内容。若未来支持文件内容分析，必须独立开关、单独授权并清晰说明上传范围。

Agent 会话上下文包含用户当前目标、已授权磁盘范围、风险偏好、工具调用结果摘要和清理计划草案。文件名、路径、规则说明及其他扫描元数据均按不可信数据处理，不能覆盖 Agent 系统指令或工具权限。

#### 4.8.7 AI 输出结构

AI 结果必须转换为受控数据，不直接执行模型返回的命令：

```json
{
	"mode": "scan",
	"summary": "优先处理可重建缓存",
	"items": [
	    {
	      "item_id": "scan-item-id",
	      "path": "C:\\Users\\User\\AppData\\Local\\Temp\\old.tmp",
	      "name": "old.tmp",
	      "purpose": "应用运行期间的临时工作文件",
	      "clean_effect": "删除后应用需要时会重新生成",
	      "recommendation": "recommended",
	      "default_selected": true,
	      "selectable": true,
	      "risk": "low",
	      "confidence": 0.91,
	      "reason": "超过保留期且属于可重建临时文件",
	      "suggested_action": "select"
	    }
	  ]
}
```

`path`、`name`、`purpose`、`clean_effect`、`risk`、`selectable` 和大小等字段由本地扫描项覆盖，模型不能伪造或修改。普通扫描结果必须关联真实 item ID；高级对话使用 `{"mode":"chat","reply":"...","items":[]}` 外壳。`suggested_action` 只允许 `select`、`keep`、`manual`，永久删除和系统动作不能由 AI 自动触发，候选必须回到本地确认流程。

#### 4.8.8 Agent 会话

- 每次 AI 清理创建独立会话，并绑定用户授权范围和扫描快照 ID。
- 会话页显示 Agent 回复、工具调用状态、当前扫描状态和方案版本。
- 工具调用以简洁状态行展示，例如“正在统计 C 盘缓存”，不展示内部思维过程。
- 用户可停止生成或取消未完成的 Agent 工具调用。
- 会话记录默认仅本地保存，可在设置中关闭保存或随时删除。
- 切换 Provider 或模型后新建会话，避免旧上下文与新模型配置混用。
- 无有效 Provider、配置测试失败或服务不可用时，基础规则扫描和手动清理仍正常工作。

#### 4.8.9 AI 安全与成本要求

- AI 结论必须显示依据和置信度，不以“AI 判断”替代解释。
- 所有 AI 候选经过本地 allowed roots、风险等级和禁止路径校验。
- 模型输出不能构造任意路径、命令或规则；只能引用本次扫描生成的 item ID。
- Agent 工具参数必须经过独立 schema 校验，未知工具、未知字段和越权范围直接拒绝。
- Agent 的系统提示词和工具定义内置且带版本号，首版不允许用户覆盖安全指令。
- 文件名和路径中即使包含类似指令的文本，也只能作为数据展示，不能触发工具调用。
- AI 请求日志默认不保存原始路径；调试日志需显式开启。发送给模型的路径只限于用户授权扫描快照，不包含文件正文。
- 调试模式也不得记录 `api_key`、Authorization 请求头或 Windows 凭据。
- 云端调用具有超时、取消、重试上限、Agent 最大工具轮次和单会话令牌限制。
- 遇到 429、计费不足或上下文过长时停止自动重试，保留当前草案并给出明确提示。
- Agent 的温度等生成参数由应用提供安全默认值，高级设置可配置但不能关闭结构化输出校验。

### 4.9 白名单与排除项

- 支持排除文件、目录、扩展名和规则。
- 内置系统保护名单不可由普通设置取消。
- 添加父目录时提示将影响的规则和预计排除范围。
- 清理前再次应用白名单，确保扫描后新增的排除规则即时生效。

### 4.10 永久删除与确认

- 清理计划展示准确路径、大小、风险、预计释放空间和永久删除数量。
- 确认区明确说明文件不会进入回收站，删除后无法恢复；按钮必须使用“永久删除 N 项”。
- 计划由扫描快照生成，使用一次性确认令牌并设置 15 分钟有效期，过期后必须重新扫描。
- 执行前逐项复核允许根目录、符号链接、文件身份、大小和修改时间；发生变化的项目跳过。
- 中高风险和大文件默认不选，只能由用户逐项主动选择后加入清理计划。
- 分页文件、休眠文件、系统组件和其他受保护对象保持只读分析，不得加入永久删除计划。
- 单项失败或跳过不终止整个任务，结果页展示实际释放、状态和原因。

### 4.11 历史与日志

- 记录扫描任务、清理任务、释放空间、规则版本、执行用户和失败原因。
- 用户可按日期查看和删除历史。
- 普通日志不得包含文件内容、密钥和完整 AI 请求。
- 提供导出诊断包功能，导出前展示包含的数据并支持路径脱敏。

### 4.12 设置

- 通用：开机启动、主题、语言、容量单位、更新设置。
- 扫描：并发度、磁盘 I/O 强度、大文件阈值、增量扫描、扫描缓存、用户范围和默认排除项。
- 清理：永久删除确认、执行前文件复核、风险提示和历史保留时间。
- 规则：规则列表、导入导出、版本和更新来源。
- AI：Agent 开关、Provider 配置、`base_url`、`model`、`api_key`、连接测试、超时、令牌限制和隐私选项。
- 隐私：数据上传范围、日志保留时间、清除本地历史。

### 4.13 计划任务与通知

计划扫描与通知属于 P1，自动清理属于 P2，包含：

- 按每周或每月计划执行快速扫描，默认只扫描、不自动清理。
- C 盘低于用户设定阈值时发送 Windows 通知，不持续重复打扰。
- 扫描完成后通知可释放空间，点击通知进入结果页。
- P2 可允许用户自动清理明确标记为低风险的项目；首次开启时单独确认并可随时关闭。
- 中高风险项目、AI 建议项和用户个人文件永不自动清理。
- 计划任务通过 Windows Task Scheduler 注册，应用卸载时移除。

### 4.14 文件占用与重启处理

- 被进程占用的普通缓存文件默认跳过，并展示占用状态。
- MVP 不强制终止用户进程，也不静默关闭浏览器或其他应用。
- 可提示用户关闭相关应用后重试对应项目。
- “重启后删除”仅允许经过审核的内置系统规则使用，用户规则和 AI 不得创建此类任务。
- 已安排的重启删除必须记录、可查看并可在重启前撤销。

## 5. 页面与交互设计

### 5.1 信息架构

建议采用左侧导航：

1. 首页
2. C 盘专清
3. 磁盘清理
4. AI 分析
5. 清理历史
6. 规则管理
7. 设置

### 5.2 关键页面

#### 首页

- 顶部显示产品名称和当前权限状态。
- 主区域显示磁盘列表及容量条。
- 紧邻容量信息提供扫描入口，不使用营销式大幅首屏。
- 下方显示最近任务与空间变化。

#### 扫描页

- 页面只保留一条顶部工具栏，标题、扫描模式、目录选择和开始/取消操作在同一栏中随状态动态变化。
- 展示当前扫描阶段、进度、路径、文件数和已发现空间。
- 提供暂停、继续和取消按钮。
- 扫描中可查看已产生的分类统计，但不可提前执行清理。

#### 结果页

- 顶部固定显示已选空间、选中项目数和“开始清理”按钮。
- 主列表按分类分组，支持展开到文件级别。
- 右侧或详情抽屉显示规则说明、风险、路径和建议。

#### AI 分析页

- Provider 配置不常驻页面；首次进入且尚未配置时，内容区中央显示“未配置”和“立即配置”按钮。
- `base_url`、`model` 和 `api_key` 在模态窗口中配置并测试；配置后入口显示在唯一顶部工具栏右侧。
- 配置测试通过后才能开始 Agent 会话，失败时弹窗保留并展示可操作的错误信息。
- 页面由对话区、工具调用状态、方案摘要和候选明细组成；窄窗口下改为上下布局。
- 对话区用于输入清理目标和追问，不能在消息气泡内直接执行删除。
- 工具状态显示“等待授权、扫描中、分析中、方案已生成、执行完成、失败”等明确状态。
- 方案摘要固定展示目标空间、预计释放空间、风险构成和当前模型。
- AI 建议与规则命中结果使用不同标识，但风险颜色遵循统一设计系统。
- 点击“审查方案”进入统一确认页；用户确认并执行后，结果回到当前会话。
- 页面提供停止 Agent、取消扫描、新建会话和打开 Provider 设置入口。

### 5.3 交互状态

所有核心页面需设计以下状态：

- 初始、加载、扫描中、暂停、已取消、成功、部分成功、失败、无结果。
- 权限不足、磁盘离线、空间不足、网络不可用、AI 服务不可用。
- 文件已变化、文件被占用、路径越界和确认计划过期。

### 5.4 通用交互规范

- 主操作在同一页面保持稳定位置，扫描进度或选中项变化不能导致按钮位移。
- 容量同时展示易读单位和精确字节值提示；单位统一使用 IEC 或 SI，不混用。
- 危险操作按钮使用明确文字，例如“永久删除 12 个项目”，不用模糊的“确定”。
- 文件列表使用虚拟滚动，支持键盘选择、范围选择和列宽调整。
- 风险不能只依赖颜色表达，同时显示文字或图标。
- Windows 缩放 100%、125%、150%、200% 下内容不重叠，最小窗口建议为 1024 x 700。
- 扫描和清理进度在任务栏显示，后台任务完成时使用系统通知。
- 无法判断总工作量时使用不确定进度，不显示虚假的精确百分比。

### 5.5 首次使用

首次启动只完成必要设置：

1. 展示安全原则与隐私摘要。
2. 让用户选择是否启用匿名诊断和云端 AI，两者默认关闭。
3. 不要求注册账号，不强迫立即执行扫描。
4. 首次进入 C 盘专清时解释低、中、高风险选择规则。

首次引导完成后不重复弹出，相关设置可在“隐私”和“清理”页面修改。

### 5.6 视觉设计方向

#### 5.6.1 风格关键词

- 现代、简约、专业、可靠、轻科技感。
- 信息优先、层级清楚、适合长时间使用。
- 整体接近现代 Windows 工具应用，不采用网页落地页或游戏界面风格。
- 科技感通过实时扫描数据、容量变化、清晰图表和细节动效表达，不依赖装饰堆叠。

#### 5.6.2 主题模式

主题设置提供三档：

1. 跟随 Windows 系统，作为默认设置。
2. 亮色主题。
3. 暗色主题。

要求：

- 用户切换主题后立即生效，不重启应用。
- 跟随系统时响应 Windows 主题变化，并记住用户选择。
- 两套主题使用相同的信息层级、尺寸和语义颜色，不能只做简单反色。
- 所有文本、图标、边框、选中态、禁用态和图表均需分别验证。

#### 5.6.3 建议色彩系统

以下色值用于设计原型，正式开发时应收敛为设计令牌，不在组件内散落硬编码颜色。

| 用途 | 亮色主题 | 暗色主题 |
| --- | --- | --- |
| 页面背景 | `#F5F7FA` | `#0F1115` |
| 一级表面 | `#FFFFFF` | `#181B20` |
| 二级表面/悬停 | `#EEF2F6` | `#22262D` |
| 主要文字 | `#171A1F` | `#F3F4F6` |
| 次要文字 | `#5F6875` | `#A7AFBA` |
| 边框/分隔线 | `#DCE2E9` | `#30353D` |
| 主操作蓝 | `#1769E0` | `#4C9AFF` |
| AI 标识青绿 | `#008C83` | `#2DD4BF` |
| 成功 | `#16803A` | `#40C463` |
| 警告 | `#B65D00` | `#F0A23A` |
| 危险 | `#C83232` | `#FF6B6B` |

配色规则：

- 蓝色只突出主要操作、选中项和扫描进度，不能让整个界面被单一蓝色占据。
- AI 功能使用青绿色小范围标识，与基础规则扫描形成稳定区分。
- 警告和危险色只表达真实状态，不能用于装饰或普通按钮。
- 图表除蓝色外使用青绿、绿色、琥珀色和中性色，保证类别可区分。
- 文本与背景对比度遵循 WCAG AA，普通文本目标不低于 4.5:1。

#### 5.6.4 字体与排版

- 优先使用 Windows 系统字体 `Segoe UI Variable`，回退到 `Segoe UI` 和系统无衬线字体。
- 正文字号建议 14 px，辅助信息 12 px，列表标题 14 至 16 px，页面标题 22 至 28 px。
- 页面内部不使用超大营销标题，标题服务于扫描和阅读效率。
- 字重以 400、500、600 为主，避免大面积粗体。
- 字母间距保持为 0；中文、数字和单位之间的格式在全局保持一致。
- 数字列、容量列和时间列右对齐或按固定规则对齐，方便纵向比较。

#### 5.6.5 布局与组件

- 左侧导航宽度稳定，内容区域采用紧凑但不拥挤的工作台布局。
- 内容区采用单一顶部工具栏；右侧操作由当前页面动态注入，切页后不得残留上一页控件或重复标题栏。
- 8 px 作为基础间距单位，紧凑控件可使用 4 px 子间距。
- 卡片圆角不超过 8 px，只用于磁盘条目、重复结果项和需要边界的独立工具，不嵌套卡片。
- 页面分区优先使用留白、分隔线和浅色表面，不把每个区块都做成悬浮卡片。
- 扫描结果以表格、树形列表和详情抽屉为主，保持较高信息密度。
- 磁盘容量优先使用横向容量条；空间分析可使用矩形树图，但必须保留列表视图。
- 按钮高度、图标尺寸和进度区域应固定，状态变化不能造成布局跳动。
- 刷新、返回、暂停、继续、删除等通用操作优先使用 Lucide 图标；不熟悉的图标提供悬停提示。
- 主要命令使用“图标 + 文字”，工具栏次要命令可使用图标按钮。
- 二元选项使用开关或复选框，扫描模式使用分段控件，规则风险使用文字与图标组合。

#### 5.6.6 动效与反馈

- 页面切换、抽屉和悬停反馈控制在 120 至 200 ms。
- 扫描时允许进度条平滑移动和当前路径轻量更新，不使用高频闪烁、粒子或持续旋转装饰。
- 清理完成可使用一次短促的数值变化和状态确认，不播放夸张庆祝动画。
- 危险操作依靠清晰文案和确认流程，不使用抖动或强烈闪光制造压力。
- 支持 Windows“减少动画”偏好，开启后关闭非必要过渡。

#### 5.6.7 明确禁止的视觉形式

- 不使用大面积渐变、霓虹发光、玻璃拟态或高饱和荧光背景。
- 不添加渐变光球、模糊色块、粒子背景和无功能装饰插画。
- 不使用过多圆角胶囊、悬浮卡片、卡片嵌套和巨大阴影。
- 不以纯黑配荧光蓝构成单一“黑客风”界面。
- 不使用超大标题、营销口号或占据首屏的品牌展示。
- 不让动画、背景纹理或 AI 标识干扰磁盘数据和风险信息。

### 5.7 主题验收标准

- 系统跟随、亮色和暗色三种模式均可正常切换并持久化。
- 首页、扫描页、结果页、确认对话框、设置页和空状态均具备两套完整主题。
- 主题切换过程中不出现白屏、颜色闪烁或不可读文本。
- 亮色与暗色主题下，低、中、高风险不能只靠颜色区分。
- 100%、125%、150%、200% 缩放下，导航、表格、按钮和对话框无文字截断或重叠。
- 键盘焦点在两种主题下均清晰可见。
- 截取 1366 x 768、1920 x 1080 和 2560 x 1440 三种桌面尺寸进行视觉验收。

## 6. 安全设计

### 6.1 禁止直接处理的对象

内置保护至少覆盖：

- Windows 引导文件、BCD、EFI 分区内容。
- 注册表 hive、活动页面文件、交换文件、休眠文件本体。
- Windows 组件存储中的普通文件删除。
- 当前应用自身运行目录及其数据库。
- 未经明确规则允许的用户 Documents、Desktop、Pictures、Videos 等内容。
- 不明符号链接、目录联接点、挂载点指向的内容。

休眠文件只能通过 Windows 支持的电源配置动作管理，不能直接删除文件。

### 6.2 路径安全校验

每个清理项执行前必须：

1. 将环境变量与相对路径解析为规范绝对路径。
2. 验证路径位于规则允许根目录内。
3. 检查是否命中全局保护名单和用户白名单。
4. 检查重解析点及最终目标是否跨越允许边界。
5. 比对扫描快照中的文件身份、大小与修改时间。
6. 根据规则风险和动作检查用户确认凭证。

### 6.3 权限模型

- 主界面默认以普通用户权限运行。
- 只有执行明确需要管理员权限的扫描或清理动作时才启动提权辅助进程。
- 主进程与提权进程通过受限 IPC 通信，请求中仅传规则 ID 和已验证的任务清单。
- 提权进程再次独立完成规则、路径和签名校验，不能盲信主进程参数。
- IPC 使用仅允许当前 Windows 用户 SID 和对应提权进程访问的命名管道 ACL。
- 主进程与辅助进程进行随机 nonce 握手，并验证进程 PID、可执行文件路径和代码签名。
- 每个清理请求携带任务 ID、请求摘要、创建时间、过期时间和一次性随机数，辅助进程拒绝重放、过期或被篡改的请求。
- 辅助进程只实现固定动作白名单，不接受命令行脚本、任意可执行路径或模型生成文本。
- 提权辅助进程完成当前任务后立即退出，不能作为长期高权限后台服务驻留。
- UAC 被拒绝或辅助进程验证失败时，只跳过需提权项目，普通用户项目仍可继续。

## 7. 技术方案建议

### 7.1 技术栈

Go 标准库不包含 GUI。可选路线如下：

| 方案 | UI 实现 | 优点 | 限制 | 结论 |
| --- | --- | --- | --- | --- |
| Wails | Go 后端 + WebView2 前端 | 复杂列表、图表和现代交互成熟 | 界面不是 Win32 原生控件，需要 WebView2 | 默认推荐 |
| Fyne | 纯 Go、自绘控件 | 前后端统一使用 Go、跨平台 | 大数据表格与 Windows 原生观感较弱 | 纯 Go 诉求时选择 |
| Walk | Go 封装 Win32 原生控件 | Windows 原生控件与系统风格 | 生态和复杂 UI 定制能力有限，仅 Windows | 强原生控件诉求时评估 |
| Gio | Go、自绘即时模式 UI | 性能与定制自由度高 | 桌面业务组件少、研发成本高 | 暂不选择 |
| 直接 Win32 | Go 调用 Windows API | 控制最完整 | 开发、测试和维护成本最高 | 仅用于必要系统能力 |

默认技术方案：

- Go 1.24 或项目启动时可用的稳定版本。
- GUI：Wails + TypeScript + React；若最终确认“界面也必须全部使用 Go”，切换为 Fyne。
- Windows 系统调用：`golang.org/x/sys/windows`，必要时封装少量 Win32 API。
- 本地数据库：SQLite，用于任务、规则、清理项、历史和设置。
- 日志：结构化日志并支持字段脱敏。
- 规则格式：JSON/YAML 文件 + JSON Schema 校验。

选型冻结前必须制作一个技术验证原型，至少验证 10 万行虚拟列表、实时扫描事件、Windows 缩放、UAC 提权通信和安装包体积。Windows 10/11 通常可使用 WebView2，Wails 安装包仍需检测运行时并在缺失时给出安装引导。

### 7.2 模块划分

```text
cmd/
  ai-clear/             桌面主程序入口
  ai-clear-helper/      可选的管理员权限辅助进程
internal/
  app/                  应用生命周期与用例编排
  scanner/              文件系统遍历、聚合和取消控制
  fsmeta/               NTFS 文件身份、硬链接、稀疏与分配空间
  incremental/          USN Journal 与扫描缓存
  cloudfiles/           OneDrive/Cloud Files 占位符状态保护
  cleaner/              清理计划、校验、执行和结果
  rules/                规则加载、校验、匹配和版本管理
  disks/                Windows 磁盘与容量信息
  ai/                   Cleaning Agent、Provider、工具注册、脱敏与输出校验
  platform/windows/     Win32 API 与 Windows 专属能力
  storage/              SQLite 与迁移
  audit/                审计日志与诊断导出
frontend/               GUI 前端
rules/builtin/          内置规则包
docs/                   产品、架构和安全文档
```

### 7.3 核心领域接口

建议将扫描、建议和执行分离：

```go
type Scanner interface {
	Scan(ctx context.Context, request ScanRequest, events chan<- ScanEvent) (ScanResult, error)
}

type CleaningAgent interface {
	Run(ctx context.Context, request AgentRequest, events chan<- AgentEvent) (AgentResult, error)
}

type Cleaner interface {
	BuildPlan(ctx context.Context, selection Selection) (CleanPlan, error)
	Execute(ctx context.Context, plan CleanPlan, events chan<- CleanEvent) (CleanResult, error)
}
```

CleaningAgent 只能通过注入的受控工具消费磁盘摘要与不可变扫描快照，并返回 item ID 方案；Cleaner 只执行经过本地规则和用户确认生成的 CleanPlan。

### 7.4 AI Agent 技术边界

AI 模块建议拆分为：

```text
internal/ai/
  agent/                Agent 循环、会话状态、轮次与预算
  provider/             OpenAI-compatible 及后续 Provider Adapter
  tools/                工具注册表、参数 schema、权限与调用审计
  prompt/               版本化系统提示词和上下文组装
  redact/               路径、用户名和设备信息脱敏
  output/               结构化结果解析与 item ID 校验
  credentials/          Windows Credential Manager / DPAPI 封装
```

Provider Adapter 负责请求协议差异，不得直接依赖扫描器或清理器。Agent 工具层只能调用应用用例接口，不直接访问文件系统。Cleaner 不接收模型原始文本，只接收本地构建并签名或绑定会话的 CleanPlan。

为避免一次向模型提交大量文件，先在本地完成规则匹配、分类、排序和聚合。Agent 按筛选条件分页查询候选项，单次工具结果设置数量与字节上限，超出时返回聚合摘要和继续查询游标。

### 7.5 并发与性能

- 目录遍历、元数据读取和统计聚合分层处理，使用有界 worker pool。
- 对机械硬盘采用较低默认并发，对 SSD 可适当提高。
- UI 事件进行节流，例如每 100 至 250 ms 更新一次，避免逐文件刷新。
- 大结果集采用分页或虚拟列表，不一次性传输到前端。
- 哈希仅用于重复文件候选，先按大小分组，避免对全盘文件直接计算哈希。
- NTFS 卷优先批量读取必要元数据，文件正文只在重复文件哈希等明确场景打开。
- 增量扫描缓存按卷隔离，并设置大小上限、版本和校验和；损坏时可安全重建。
- 云盘占位符、离线文件和重解析点元数据读取必须使用不会触发内容召回的 Windows API。

### 7.6 数据存储

建议最少包含以下表：

- `settings`：应用设置。
- `rule_packages`、`rules`：规则包和规则版本。
- `scan_jobs`、`scan_items`：扫描任务和结果。
- `scan_volumes`、`scan_checkpoints`：卷身份、USN 状态、扫描缓存版本和恢复检查点。
- `clean_jobs`、`clean_items`：清理计划和执行结果。
- `ai_providers`：Provider 非敏感配置和 Credential 引用。
- `ai_sessions`、`ai_messages`：Agent 会话、消息和工具调用摘要，默认不保存完整路径。
- `audit_events`：安全与操作审计。

`scan_items` 至少记录逻辑大小、分配空间、预计可释放空间、卷 ID、文件 ID、硬链接数量、云文件状态、所属用户 SID 和快照校验字段。

AI 密钥使用 Windows Credential Manager 或 DPAPI 加密保存，不以明文写入配置文件或 SQLite。

### 7.7 数据保留与清理

- 扫描明细默认保留 7 天，到期后删除；汇总历史默认保留 180 天。
- 清理审计记录默认保留 180 天，用户可主动清除非安全必要记录。
- AI 临时请求数据在响应完成后从内存释放，不默认落盘。
- 卸载程序提供“保留设置与历史”和“删除全部应用数据”两个明确选项。

### 7.8 安装、更新与签名

- 提供 x64 安装包；便携版是否发布在 V1 前决定。
- 主程序、提权辅助进程、安装包和更新包均进行代码签名。
- 安装目录不可被普通用户随意写入，用户规则与数据库保存在用户数据目录。
- 自动更新先下载到独立临时目录，校验签名与哈希后再安装。
- 更新失败能够继续运行旧版本，不破坏数据库和清理历史。
- 数据库迁移需支持备份与失败回滚，不承诺降级版本读取新数据库。

## 8. 非功能需求

### 8.1 兼容性

- 支持 Windows 10 22H2 和仍受支持的 Windows 11 版本。
- 首版支持 NTFS、常见本地固定磁盘和 x64 架构。
- 对 ReFS、可移动磁盘、网络盘和 ARM64 先检测并明确提示支持状态。
- 支持长路径；不假设所有路径都小于传统 `MAX_PATH`。
- 多用户功能以 Windows SID 识别账户，不依赖可能重名或变化的显示名称。
- ReFS、FAT/exFAT 等卷不套用 NTFS 硬链接、USN 或分配空间假设，不支持的能力明确降级。

### 8.2 性能

- 冷启动目标小于 3 秒（普通消费级设备，不含自动扫描）。
- 50 万文件扫描期间 GUI 不出现持续无响应。
- 后台扫描内存应保持有界，不能将全盘所有元数据永久堆积在内存。
- 取消操作目标在 1 秒内停止派发新任务，在当前不可中断系统调用返回后结束。

### 8.3 稳定性

- 应用崩溃不能留下无法追踪的执行状态；每项永久删除结果必须可审计。
- 清理记录采用事务或追加式状态更新。
- 规则解析失败只禁用对应规则，不阻止应用启动。
- AI、网络和更新模块故障不影响本地基础清理。

### 8.4 隐私与安全

- 默认本地处理、最少采集、用户主动开启云端 AI。
- 不收集文件内容和完整路径作为遥测。
- 安装包、更新包和在线规则包需要签名验证。
- 应用更新、AI 服务和规则更新使用 HTTPS。
- 提供隐私说明、第三方组件清单和开源许可证页面。

### 8.5 可测试性

- 规则匹配、路径边界、白名单和风险策略必须有单元测试。
- 使用临时目录构造文件树进行扫描与清理集成测试。
- Windows 专属行为在 Windows CI 或测试机执行。
- 对路径遍历、重解析点、竞态替换和恶意规则进行安全测试。
- 清理测试不得依赖或修改开发机真实系统目录。
- 使用专用测试卷覆盖硬链接、稀疏文件、NTFS 压缩、不同簇大小和多规则重复命中。
- 使用 Cloud Files 测试 Provider 验证占位符扫描不会触发内容下载。
- 使用多个本地 Windows 账户验证 SID 隔离、权限不足和管理员扫描范围。
- 对 USN Journal 正常、不可用、回绕、卷替换和缓存损坏场景进行降级测试。

### 8.6 可观测性与错误处理

- 每个任务生成唯一 ID，UI 错误、日志和诊断包可通过该 ID 关联。
- 用户可读错误包含“发生了什么、哪些项目受影响、下一步怎么做”，不直接显示内部堆栈。
- 开发日志包含规则 ID、阶段、错误码和耗时；路径默认脱敏。
- 发布版本捕获未处理错误并生成本地崩溃报告，只有用户明确同意才上传。
- 对扫描速度、跳过率、清理成功率和规则误报反馈预留统计接口，匿名遥测默认关闭。

### 8.7 发布质量门槛

- P0 功能和安全验收全部通过，不允许以已知严重误删风险发布。
- 核心包通过 `go test`、静态检查和 Windows x64 构建。
- 安装、升级、卸载、UAC 提权和系统重启场景在真实 Windows 测试机验证。
- 内置规则必须经过至少两个受支持 Windows 版本验证。
- 每次发布附带规则版本、数据库迁移版本和已知问题清单。

## 10. MVP 验收标准

### 10.1 功能验收

- 能列出本机固定磁盘及正确容量。
- 能对 C 盘和指定其他盘发起、暂停、继续、取消扫描。
- 至少提供 10 条经过测试的低/中风险内置清理规则。
- 扫描结果能追溯到规则，支持查看文件级明细和排除项目。
- 每条规则都明确包含 `default_selected`，且中高风险与分析项默认不选。
- 结果页默认显示文件列表，并可切换到可展开、收缩的文件夹聚合模式。
- 大文件能正常扫描和列出，但全部默认不勾选。
- 清理前显示预计空间和风险，清理后显示实际结果。
- 中高风险项目默认不选，高风险动作必须二次确认。
- 支持白名单，且白名单在执行前再次生效。
- 所有可执行文件清理均为永久删除，并具有明确不可恢复提示。
- 无管理员权限时仍能完成当前用户范围扫描；需提权项目有明确提示。

### 10.2 安全验收

- 使用异常环境变量、`..`、符号链接、目录联接点或挂载点不能突破规则允许根目录。
- 扫描完成后替换文件或路径，执行阶段能够发现变化并跳过。
- 任意单条规则不能删除未声明 allowed roots 之外的文件。
- AI 输出即使包含路径或命令也不会被直接执行。
- 应用异常退出后，已完成和未完成的单项状态可从历史中准确识别。

### 10.3 性能验收

- 在包含 50 万个测试文件的目录中扫描时界面可交互且能取消。
- 大结果集不会因一次性 UI 渲染造成明显卡死。
- 无权限文件、被占用文件和超长路径均以单项错误处理，不造成任务崩溃。

### 10.4 端到端验收用例

| 用例 | 前置条件 | 操作 | 期望结果 |
| --- | --- | --- | --- |
| E2E-01 C 盘快速扫描 | 普通用户权限 | 启动快速扫描并等待完成 | 返回分类结果；权限不足项单独标记，任务整体成功 |
| E2E-02 中途取消 | 标准扫描运行中 | 点击取消 | 停止派发新任务，状态变为已取消，不允许基于残缺结果清理 |
| E2E-03 白名单拦截 | 某目录已命中规则 | 扫描后将目录加入白名单再清理 | 执行前复核将该目录全部跳过 |
| E2E-04 文件被替换 | 扫描后修改候选文件 | 执行清理 | 快照校验失败，该文件跳过并记录原因 |
| E2E-05 永久删除确认 | 已选择可清理文件 | 打开计划并取消，再次打开后确认 | 取消时不删除；确认时明确提示不可恢复并只删除计划内文件 |
| E2E-06 按需提权 | 选择需管理员权限项目 | 确认清理并通过 UAC | 只执行已确认且复核通过的提权任务 |
| E2E-07 AI 恶意输出 | 模型返回任意路径或命令 | 提交 AI 结果 | schema 或本地策略拒绝，不执行任何命令或新增路径 |
| E2E-08 断网降级 | 无网络 | 使用基础扫描并进入 AI 页面 | 基础功能正常；AI 明确提示不可用且可重试 |
| E2E-09 应用异常恢复 | 清理执行中模拟异常退出 | 重新启动应用 | 历史能区分已完成与未执行项目，不重复删除或扩大范围 |
| E2E-10 超大结果集 | 扫描结果超过 10 万条 | 筛选、排序和滚动 | 页面保持响应，不一次性加载全部明细 |
| E2E-11 Provider 配置 | 填写有效 `base_url`、`model` 和 `api_key` | 测试连接并保存 | 测试成功，非敏感配置落库，密钥只进入 Windows 安全存储 |
| E2E-12 Provider 鉴权失败 | 填写无效密钥 | 测试连接 | 明确提示鉴权失败，不记录或回显完整密钥 |
| E2E-13 Agent 越权工具 | 模型请求命令执行或直接删除 | 运行 Agent | 工具注册表拒绝请求，记录安全事件并保持会话可控 |
| E2E-14 Agent 清理闭环 | Provider 有效且已有扫描结果 | 要求释放指定空间并审查方案 | Agent 只引用有效 item ID，用户确认后由 Cleaner 执行并返回结果 |
| E2E-15 默认选择 | 结果同时包含低、中、高风险项目 | 打开结果页并使用“全选推荐项” | 仅 `default_selected: true` 的低风险推荐项被选中 |
| E2E-16 大文件选择 | 扫描范围包含多个超过阈值的文件 | 完成大文件扫描 | 大文件按大小列出且全部未选，用户可逐文件主动勾选允许处理项 |
| E2E-17 结果视图切换 | 文件列表中已有部分选择 | 切换文件夹模式、展开目录后再收缩并切回 | 文件夹聚合准确，视图切换和折叠不改变原选择 |
| E2E-18 NTFS 空间计算 | 测试卷包含硬链接、稀疏和压缩文件 | 扫描并选择清理 | 逻辑、分配和预计释放空间正确，硬链接不重复计算 |
| E2E-19 云盘占位符 | OneDrive 目录包含仅云端文件 | 执行目录扫描 | 不触发文件下载，仅显示本地实际占用，未同步项不进入候选 |
| E2E-20 多用户范围 | 管理员环境包含多个本地用户 | 只授权扫描指定用户 | 结果按 SID 隔离，未授权用户目录不被扫描 |
| E2E-21 增量扫描降级 | USN 日志回绕或缓存损坏 | 启动增量扫描 | 自动改为完整扫描，不使用失效结果创建计划 |
| E2E-22 磁盘中断恢复 | 扫描中磁盘离线后以同一卷身份恢复 | 继续任务 | 任务安全恢复；卷身份变化时终止并要求重扫 |
| E2E-23 计划过期 | 清理计划超过 15 分钟 | 尝试执行 | 拒绝过期令牌，要求重新扫描并确认 |
| E2E-24 提权请求重放 | 重复发送已执行或过期 IPC 请求 | 辅助进程接收请求 | 请求被拒绝并记录安全事件 |
| E2E-25 Agent 能力测试 | Provider 只能返回文本但不支持结构化工具调用 | 测试 Provider | 连接可达但能力不合格，不能标记为可用 Cleaning Agent |
| E2E-26 计划导入复核 | 导入本机之前导出的过期计划 | 尝试执行 | 要求重新扫描和逐项复核，不能直接删除 |
| E2E-27 分页文件帮助 | 系统存在 `pagefile.sys` | 查看规则并点击问号 | 显示用途、风险和手动设置入口，复选框禁用且不计入自动释放 |
| E2E-28 误报反馈 | 用户将命中项标记为“不是垃圾” | 选择永久白名单 | 项目立即取消选择，后续扫描不再命中，匿名反馈不包含名称或完整路径 |

### 10.5 MVP 完成定义

同时满足以下条件才视为 MVP 完成：

1. P0 需求均有实现、测试和用户可见的错误处理。
2. 首批至少 10 条内置规则完成 Windows 实机验证。
3. 不存在已知的越界删除、白名单失效或不可追踪清理问题。
4. 能生成签名或内部测试签名的 Windows x64 安装包。
5. 使用说明、隐私说明、规则说明和永久删除风险说明随版本交付。
6. 在干净安装、覆盖升级和卸载三条路径上通过验证。

## 11. 待确认事项

以下决定会影响正式技术设计，但不阻碍 MVP 原型启动：

1. GUI 选用 Wails、Fyne 还是 Walk；本文默认建议 Wails，若“纯 Go UI”是硬性条件则选择 Fyne。
2. 是否只支持 x64，还是首版同时支持 ARM64。
3. OpenAI-compatible 首版使用单一兼容接口，还是同时实现多种协议 Adapter。
4. 是否需要提供预置 Provider 模板，还是只提供完全自定义配置。
5. 首批重点支持的浏览器、聊天工具、开发工具和游戏平台。
6. 是否需要软件自动更新、规则在线更新和匿名遥测。
7. 产品分发方式：独立安装包、便携版或 Microsoft Store。
